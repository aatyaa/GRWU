The first four articles each taught one skill: reading a ring, taking a signal apart into tones, saying how sure you are, and fitting a model. Real work strings them together, and the result is a sentence in a paper. Between the data and that sentence there are dozens of steps, and any of them can go wrong without a sound.

This article follows one small claim from a public data file to a sentence, then breaks each link on purpose to see which habits would have caught the break. None of the habits is clever. All of them are what separates a number from a number someone else can check.

The most dangerous mistakes are the ones that give reasonable-looking numbers. A frequency four times too high still looks like a frequency. That is why each check works *without* knowing the answer: the rate is read from the file, the size is compared with what a detector can measure, and the fingerprint is compared with the one published.

The last option is not a mistake at all, and it teaches the most. Averaging four-second segments instead of one-second ones moves the quietest point from {c.quietest.f} Hz to {c.variants.segments.f} Hz. Both computations are correct. The detector was about equally quiet over a broad stretch, and which point is lowest depends on the method. So a better claim is one that survives the choice: between {c.floor.from} and {c.floor.to} Hz, the noise sat near {scientific(c.floor.one)} per √Hz with one-second segments, and {scientific(c.floor.four)} with four-second ones.

## Test your code against a reference

Every function this site applies to data was first run beside an independent program, usually scipy or numpy, on the same inputs, and the two answers compared number by number. It sounds like overkill until you meet the Hann window.

The window that tapers each segment before a spectrum is computed comes in two kinds. The **symmetric** one ends at zero on both sides; it is what `np.hanning` returns. The **periodic** one is what scipy's spectrum uses; it leaves out the final zero, so that copies placed end to end repeat smoothly. Fredric Harris explained in 1978 why spectral estimates need the periodic kind. On a plot they look the same.

## Which digits are real

The spectrum above has no randomness in it: run it twice and you get the same numbers to the last digit. A sampler is different. It draws random numbers, so its median comes out a little different on every run.

A **seed** fixes the random numbers, so the same code gives the same samples every time. That is essential for checking. But it hides a question: which digits would change with a different seed? Below, a made-up <Term id="posterior">posterior</Term>, {WIDTH} Hz wide, is sampled with twenty different seeds.

<Figure kind="schematic" width="medium">
  <SeedSpread client:visible />
  <Fragment slot="caption">
    The median of the same posterior, sampled with twenty seeds. Draw more samples and more digits
    hold still, but never more than the posterior's width deserves.
  </Fragment>
</Figure>

With a thousand samples, the medians wander by about {spread1k.toFixed(1)} Hz, so the digit after the decimal point is noise. With a hundred thousand they wander by {spread100k.toFixed(2)} Hz, and one more digit holds. But the posterior is {WIDTH} Hz wide either way. The honest quote is {CENTRE} ± {WIDTH} Hz, and the extra digits say something about the computer, not about the black hole.

  Quote a number to the precision of its error bar, <em>not the precision of your computer.</em>
</Pull>

<MathLayer id="m-mc-error" title="how much a sampled median wanders">
  <Given>*N* independent samples from a bell-shaped posterior of spread σ.</Given>
  <Steps>
    <Step tex="\operatorname{Var}(\hat m) \approx \frac{1}{4 N\, p(m)^2}">
      The median of *N* samples scatters around the true median by an amount set by how dense the
      posterior is there, *p*(*m*).
    </Step>
    <Step tex="p(m) = \frac{1}{\sqrt{2\pi}\,\sigma} \;\Rightarrow\; \sigma_{\hat m} \approx \sqrt{\frac{\pi}{2}}\,\frac{\sigma}{\sqrt N} \approx 1.25\,\frac{\sigma}{\sqrt N}" hinge>
      For a bell curve, the median wanders by about 1.25 σ/√*N*: a quarter of a hertz for σ = 6 Hz
      and *N* = 1000.
    </Step>
    <Step tex="N \to N_{\text{eff}}">
      For samples from a chain that remembers itself, use the effective number of samples from
      [How Sure Is Sure?](../how-sure-is-sure/), which can be far smaller.
    </Step>
  </Steps>
  <Means>
    The wander shrinks only as one over √*N*: a hundred times more samples buys one more digit.
    The width σ of the posterior does not shrink at all.
  </Means>
</MathLayer>

## Reading someone else's posterior

For each detection, the collaborations publish their posterior samples alongside the data: thousands of rows, one per sample, with a column for each parameter. The real files are in a format called HDF5, and tools such as PESummary read them. Inside, the job is the same as below: pick a column by its name, take its median, and quote a <Term id="credible-interval">credible interval</Term>.

## What a claim should carry

In 2013 Geir Kjetil Sandve and colleagues wrote ten simple rules for computational work that others can repeat. Most of them have appeared in this article already. Record how every result was produced. Never edit data by hand. Note the random seeds. Keep the data behind every plot. Connect every number in the text to the code that made it.

A claim that follows them carries a short trail with it:

- **the data**, with where it came from and its fingerprint;
- **the method**, with the choices made, such as the segment length;
- **the code**, with its version and the tests it passed against a reference;
- **the seeds**, if anything was random;
- **the uncertainty**, quoted to the precision it deserves;
- **the assumptions**, including the model, which [What the Wrong Model Knows](../what-the-wrong-model-knows/) showed can fail while every check passes.

This article follows its own advice. Every number it quotes about GW150914 is computed from the file when the site is built, and the build stops if the file's fingerprint changes.
